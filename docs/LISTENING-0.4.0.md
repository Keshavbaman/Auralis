# Auralis 0.4.0 — Your Listening and smoother UI

New listening dashboard follows the supplied reference composition: navy surfaces, Today/Daily/Monthly/Total selectors, prominent real listening totals/averages, blue gradient charts with dotted mean lines and tappable values, a text sharing action with no book titles included, month comparison, weekly activity streak, finished-title carousel and library growth. Goals, calendar, 30-day and annual charts, extended insights and Wrapped exports remain under “Goals, calendar & more insights”. No sample data is shown in the installed app.

Today uses hourly elapsed listening; Daily uses seven calendar days; Monthly averages seven calendar months including quiet months; Total uses actual listening time over calendar years. Weekly continuity requires at least one listening day per Monday-based week; a quiet current week retains the preceding streak until that week ends. This is separate from the configurable daily streak. Library growth uses when currently owned books were added, and is labelled accordingly. No missing past library history or recording metadata is fabricated.

Performance changes: shared history stream, library coverage and stats/report work on Dispatchers.Default, fast position collection isolated inside the mini-player instead of the entire app/navigation shell, catalogue screens use periodic persisted progress while the player/mini-player keep live positions. Plot animation reads its clock during drawing rather than recomposing the screen. Existing reduced-motion preferences and shared artwork/player transitions remain.

The installed optimized build is non-debuggable and minified with R8; it includes dependency startup profiles. Local distribution uses the existing development signing certificate to allow an in-place update. Use a separately secured release key for store distribution. Android ART speed compilation was completed on the connected phone after measurement. No device refresh-rate, temperature limits, animation-scale or power settings were overridden.

Validation: 43 unit tests passed, including five new dashboard accounting cases. Three dashboard layout/interaction tests passed (phone, 320dp at 1.5 font scale, tablet). Three navigation/tablet regression tests passed after updating the title selectors for the current Library header. Debug lint and optimized vital lint passed; debug/verification/optimized builds succeeded. Inspected the production dashboard on the Android phone. Android-only signed instrumentation compared the optimized app’s SQLite snapshot with the pre-update backup: books/files/chapters/positions/speeds/history/achievements/collections/source references unchanged; last-played timestamps excluded from comparison. A standard unminified AndroidX test runner could not attach to the minified runtime (missing unobfuscated Kotlin symbol); that test harness failure was isolated, and the independent Android-only probe was used for data validation. Normal optimized app startup and saved playback-controller restoration were checked on-device.

Performance evidence: docs/performance/before-debug.txt and after-optimized.txt. Repeated library up/down swipe sequence (eight 350ms swipes, same book library), frame counters reset before each run. Before: 362 frames, 189 janky (52.21%), median 21ms, p95 42ms. After: 630 frames, 30 janky (4.76%), median 9ms, p95 13ms. These are short device observations, not a Macrobenchmark or a guarantee of universal frame rate. Thermal state and refresh governor were not fixed; observed thermal status was 2 before and 1 afterwards, with other media activity present. Changes and optimized build were tested together, so their individual contributions were not isolated.

Android guidance consulted: https://developer.android.com/develop/ui/compose/performance and https://developer.android.com/codelabs/jetpack-compose-performance
